# Known-answer vectors

`hcfs-vectors-v1.json` is generated by the hcfs repo, not by this one. hcfs is
the oracle for every wire and crypto fact; these vectors are the handshake that
keeps the Python reimplementation byte-identical to the Rust client.

## Where it comes from

| | |
|---|---|
| Exporter | `hcfs-client/tests/export_sdk_vectors.rs` (hcfs repo, Phase 0 Task 0.3) |
| Source of truth | `hcfs-client/tests/vectors/hcfs-vectors-v1.json` |
| Regenerate | `HCFS_WRITE_VECTORS=1 cargo test -p hcfs-client --test export_sdk_vectors` |
| Drift guard | the same test, run without the env var, in hcfs CI |

Copy the file here verbatim. The two copies must be byte-identical; a diff
between them is a bug in whichever repo was updated alone.

## Schema this repo replays

`tests/test_vectors.py` reads these keys. If the exporter lands with different
field names, update the replay in the same pull request that commits the file:

```
version, master_mnemonic, account_ss58, base_nonce_hex
derivation[]     label, folder_mnemonic, folder_hash, seed_hex,
                 signing_key_hex, verifying_key_hex, encryption_key_hex
cipher[]         plaintext_len, plaintext_hex, key_hex, ciphertext_hex,
                 ciphertext_hash
hashes           path, path_hash, salted_plaintext_hex, salted_hash
manifest         plaintext_hex, key_hex, relative_path, timestamp,
                 revision_seq, tos_text, and the manifest object itself
mnemonic_store[] iterations, salt_b64, iv_b64, password, mnemonic, file
mnemonic_blob    passphrase, mnemonic, salt_b64, nonce_b64, kdf, blob
rename_text      pairs[] (old_hex, new_hex), text
```

## Bumping the version

Changing any pinned value is a breaking change to stored data: a new folder
mnemonic orphans every folder already registered under the old derivation.
Bump `version`, rename the file, and update both repos in the same change.
